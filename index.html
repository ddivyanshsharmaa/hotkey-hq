Each coloured dot is one layer that binds that key; the number is how many shortcuts use it. Hold Ctrl, Alt or Shift and the keyboard lights up every key that combination unlocks, coloured by whichever layer wins. Click any key for the full list. Only enabled layers are counted. Keys marked fn share their position with a hardware control on a laptop — depending on your BIOS "action keys" setting, plain F5 may send brightness or volume and you'd need Fn+F5 for the real F5. Fn itself is handled in the keyboard firmware and never reaches Windows, so nothing here can see or rebind it.

Windows & PowerShell realities

  • Capture mode has a hard ceiling. While it's on, this window swallows every shortcut it can reach and explains it instead of running it — including the browser-level ones like Ctrl+S and Ctrl+P, and page zoom. What it cannot reach is anything Windows claims first: Win+ anything, Alt+Tab, Alt+F4, Ctrl+Alt+Del, Ctrl+Shift+Esc. Those never reach any app, so they're listed below but can't be live-tested. Intercepting them would need a system-wide keyboard hook, which is exactly how keyloggers work — not worth it for a reference tool.
  • Ctrl+Shift+Esc is a real collision. Windows opens Task Manager; Claude's VS Code extension wants it for "Open in New Tab." The OS wins, so the extension binding effectively doesn't fire.
  • "Meta" in Claude's docs means Alt here. Meta+P/O/T = Alt+P/O/T on Windows.
  • Claude's Cmd+K clear-screen is dead on Windows. It needs the Super modifier, which Windows terminals don't report. Bind something else — press an unused combo above and assign chat:clearScreen.
  • Shift+Enter for a newline needs a one-time /terminal-setup in the VS Code terminal. Ctrl+J works everywhere with no setup.
